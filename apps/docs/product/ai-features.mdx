Harly's AI features are optional and off until you configure a provider. They
assist the hiring team; they never make a hiring decision. Every AI output is a
suggestion a human reviews and owns.

## Enable AI

<Steps>
  <Step title="Choose a provider">
    Open **Settings → AI**, choose **Configure AI**, and select a provider.
    Harly supports OpenAI, Anthropic, Google Gemini, xAI, OpenRouter, Groq,
    DeepSeek, Mistral, Together AI, Fireworks AI, Cerebras, Azure OpenAI,
    Ollama (local), and any OpenAI-compatible endpoint. You bring your own API
    key. Harly does not proxy through a shared key.
  </Step>
  <Step title="Pick a model">
    Search the **Model** list or type any model ID, even one that isn't
    listed. For Azure OpenAI, enter your **Deployment name**. Except for
    Ollama and OpenAI-compatible endpoints, the list comes from
    [models.dev](https://models.dev), with a built-in copy that works offline.
  </Step>
  <Step title="Add the API key">
    Paste the API key from your provider. It is stored encrypted and never
    returned to the browser. Ollama and OpenAI-compatible endpoints accept a
    blank key when the server doesn't need one.
  </Step>
  <Step title="Test and save">
    Choose **Test connection** to confirm the key and model work, then
    **Save changes**.
  </Step>
  <Step title="Enable specific features">
    Turn on only the features you want. Nothing is sent to the provider until a
    feature is both enabled and actively used.
  </Step>
</Steps>

Until a provider is configured and usable, Harly hides the Harly AI buttons,
the chat launcher and its shortcut, the AI entries in the command palette, and
the AI panels.

### Custom API endpoint

Choose **Custom API endpoint** in the configure form to send requests through
your own gateway, proxy, or model server instead of the provider's default URL.
Azure OpenAI and OpenAI-compatible always need an **API endpoint**. Harly checks
the endpoint before saving:

- Hosted providers accept only their own domain. For example, Azure OpenAI
  accepts hosts under `.openai.azure.com`, `.cognitiveservices.azure.com`, or
  `.services.ai.azure.com`. To use a gateway on another host, choose
  **OpenAI-compatible**.
- **OpenAI-compatible** and **Ollama (local)** accept any public `https://`
  host, such as a LiteLLM gateway or a vLLM server.
- Localhost and private network addresses are blocked unless the server sets
  [`HARLY_ALLOW_LOCAL_LLM=1`](/deployment/configuration#updates-and-ai-agents).
  Plain `http://` works only for those local addresses. Private network
  addresses work only with **Ollama (local)** or **OpenAI-compatible**.

When Harly rejects an endpoint, the error says which rule applied.

<Warning>
  AI output is advisory and the chat assistant never silently applies a
  workflow. A workspace owner can explicitly authorize a reviewed automation
  with a rule such as `ai.score < 50`, including a rejection email or a
  candidate-data erasure step. A person owns the rule and its policy; the
  workflow runtime enforces permissions, durable effects, retries, and legal
  holds.
</Warning>

## What AI can do

### Candidate matching

Rank or summarize how an application fits a job's requirements, as a starting
point for review. The output appears alongside the application — the recruiter
reads it and decides.

This is a triage signal, not a filter. Use it to prioritize which applications
to open first, not to skip reading them.

Scoring is evidence-backed:

- **Verified quotes.** Each criterion gets a score from 0 to 100 and a short
  quote copied from the résumé or application answers. Harly checks every quote
  against the text the model received and drops any quote it cannot find. A
  criterion without a verified quote shows no evidence instead of an invented
  one.
- **One rubric per job.** When a job has a published rubric, every candidate
  for that job is scored against the same criteria, in the same order, with
  the same labels. This keeps scores comparable across applicants.
- **Résumé and answers as data.** Harly passes the résumé and application
  answers to the model as clearly delimited, untrusted data. Instructions
  written inside a résumé are not followed.
- **No names or locations.** The candidate's name and location are never part
  of the scoring prompt, whether or not anonymization is on. They are not
  needed to judge fit.
- **Malformed answers are salvaged.** If the provider returns a score in a
  slightly broken format, Harly recovers the usable result instead of falling
  back to its built-in rules.
- **Bulk scoring skips duplicates.** Scoring many applications at once does not
  re-score the same application twice.

The evaluation card shows which engine produced the score. An AI score shows the
model name. A score from Harly's built-in rules shows **Harly Algorithm** with
the rules version, and a manual run that fell back shows the warning "Scored
with Harly's built-in rules: the AI provider didn't return a usable answer."

<Accordion title="Troubleshooting: scores fall back to Harly's built-in rules">
  Harly uses its built-in rules when the provider does not return a usable
  answer. Check the following:

  - The API key in **Settings → AI** is valid and has quota.
  - The selected model is available to your provider account.
  - You run Harly 0.3.3 or later if you use an OpenAI reasoning model (the
    o-series, or `gpt-5` and newer). Earlier versions sent a `temperature`
    setting that these models reject, so every score fell back to rules. From
    0.3.3, Harly omits `temperature` for these models.

  After you fix the cause, run the evaluation again from the candidate's
  evaluation card.
</Accordion>

### Assisted drafting

Draft candidate messages and job descriptions you review and edit before
sending. The draft is editable from the moment it appears; you own the final
text.

Common uses:
- First outreach message after an application
- Rejection email with a reason
- Interview invitation with agenda

### Candidate anonymization

Resume anonymization is a workspace setting in **Settings → AI**. When it is on:

- Candidate profiles hide identifying details on screen (names, contact details,
  and links are blurred until a reviewer reveals them for that candidate). This
  is a screen mask. The stored records are not changed.
- AI scoring, matching, and interview note summaries receive the candidate under
  the alias "Candidate". Names, email addresses, phone numbers, links, social
  handles, street addresses and location are removed from what is sent. Names
  are also removed from the candidate's résumé, headline, application answers
  and interview notes.
- The chat assistant also receives the page you are on as "Candidate profile"
  or "Workspace section", never the candidate's name.
- The chat assistant's tool results get the same treatment. Each candidate is
  shown as "Candidate" with a short code that stays the same for that candidate
  within one conversation, and ids are kept so the assistant can still act on
  the right record. Names, email addresses, phone numbers, links, avatars,
  addresses, locations and mail-header addresses are removed from what the model
  receives. Names in free text are masked wherever a known candidate's name
  appears. A candidate is recognized when the result or the tool call names
  them by id, links to their profile, or gives their email address. A name that
  appears with no such reference is not masked. A single-word name is masked only
  when it starts with a capital letter and is not followed by a day number, so
  "May 12" stays a date. If redaction fails, the assistant receives a withheld
  notice instead of the result. If a tool call fails, the assistant receives a
  generic failure notice instead of the error message. The screen still shows the
  results and errors.
- Features that cannot work without knowing who the candidate is are paused,
  and the screen says so: duplicate detection, email drafting, mailbox
  assistance, AI resume autofill on the apply form, AI resume summaries on
  upload, and scorecard comment refinement. The standard parser or the manual
  path is used instead.

Anonymization removes what Harly knows about the candidate, including names that
appear in the résumé text. It cannot remove a name that is not in the candidate
record, such as a nickname that appears only in a résumé, and it does not
change the job description or the rest of the workspace.

### Chat

Ask questions about candidates, jobs, pipeline health, or automations. The assistant
operates within your active workspace using real-time tools governed by role-based
permissions. When opened alongside a specific candidate or job, it automatically incorporates
that item's context while respecting your tenant boundaries.

  <img
    src="/images/features/ai-assistant.webp"
    alt="Harly AI assistant open beside a candidate pipeline with a prompt asking who needs review."

</Frame>

Examples:
- "Summarize this candidate's relevant experience."
- "What questions has this candidate not answered yet?"

#### Open the assistant

The assistant launcher is always visible at the bottom of the dashboard and
shares that surface with notifications. Select it to open the chat panel.

In the panel:

- Press `Enter` to send a message.
- Type `@` to mention a candidate, job, or other record.
- Press `Escape` to close the panel. Focus returns to where you were.

Press `?` anywhere in the dashboard to see the full list of keyboard shortcuts.

#### Rich answers

Besides text, the assistant can answer with interactive blocks: candidate and
task lists, tables, bar and line charts, stat tiles, choice buttons, short
forms, and notes. Blocks stay on screen while the rest of the answer streams in.

#### Reply language

The assistant replies in the language of your latest message, not the language
of earlier turns or of the workspace data. Product names, candidate names, URLs,
and values you typed are kept as written.

#### Brand the assistant

Open **Settings → AI** and use the **Assistant** card to change how the
assistant appears to your team. Only your workspace sees the change.

- **Name**: up to 24 characters. The default is "Harly AI".
- **Avatar**: the Harly mark, or your own square PNG, JPG, SVG, or WEBP image up
  to 5 MB.
- **Show "Powered by Harly"**: adds a small attribution under the message box
  when the assistant has a custom name.

<Note>
  Multi-turn chat works with OpenAI reasoning models (the o-series, or `gpt-5`
  and newer) from Harly 0.3.3. On earlier versions, follow-up messages after a
  tool call could fail on these models.
</Note>

### Automation authoring

Harly AI can propose complete workflows in the Automations Builder. It can
discover the enabled action and integration catalog, resolve jobs, stages,
templates, and other workspace resources, preserve branches, delays, waits,
and approval outcomes, then simulate the proposal before anything is applied.
The proposal shows a graph diff and branch-coverage report and uses a
revision/content-hash check when the owner applies it. For example, an owner
can ask for `application.created` → `ai_score` → `ai.score < 50` → reject,
send a specific email, and queue durable candidate-data erasure, with an
alternative manual-review branch for scores of 50 or more.

The complete tool, permission, integration, and simulation contract is
published in the generated [automation capability matrix](/product/automation-capability-matrix.generated).
CI verifies that matrix against the runtime manifests and legacy registry so
the documentation cannot drift from what Harly can actually execute.

## What leaves your server

This table lists what each AI feature sends to your configured provider, and what
changes when candidate anonymization is on. Harly sends nothing to a provider
for a feature you have not enabled or used.

| Feature | What is sent to the provider | With candidate anonymization on |
| --- | --- | --- |
| Candidate scoring (on apply, manually, in bulk, or by an `ai_score` automation) | Job title, description, requirements, sector, experience level, education and keywords, plus the job's published rubric criteria. Candidate headline, skills (up to 20), years of experience, résumé text (first 12,000 characters) and application answers (600 characters each). Candidate name and location are never sent. | Headline, résumé and answers are redacted. Job text is unchanged. |
| Semantic matching (OpenAI embeddings only) | Job text. Candidate name, headline, skills, years of experience and résumé text, to build each candidate's vector | Candidate name is not included, and the headline and résumé are redacted. Location is never included. A vector built before the setting was turned on stays as it was until the candidate's record is next edited. |
| Duplicate detection | Name, email, headline and skills of the candidate and of up to 10 similar candidates | Paused. Nothing is sent. |
| Interview note summary | Notes (first 8,000 characters), candidate name, job title, interview type | Candidate name is removed from the notes and replaced with "Candidate". |
| Interview brief | Candidate name, headline, location, skills, résumé (first 8,000 characters), job text, interviewer notes and the existing score | Not yet covered. The name, location, résumé and notes are still sent. |
| Résumé summary on upload | Résumé text (first 16,000 characters) | Paused until the upload knows the candidate's name. The standard parser is used. |
| Résumé autofill on the public apply form | Applicant's résumé text (first 12,000 characters) and job keywords | Paused. The standard parser fills the form. |
| Email drafts | Candidate name, job title, company, sender name, the email thread (addresses and up to 50 messages), and your internal AI score and summary, which the model is told never to repeat | Paused. Nothing is sent. |
| Mailbox summary and reply | The email thread, including addresses | Paused. Nothing is sent. |
| Scorecard comment refinement | The comment text and role title | Paused. |
| Scorecard attribute suggestions, job description drafts, screening questions | Job details only | No change. No candidate data is sent. |
| Pipeline headline | Aggregate counts only | No change. |
| Chat assistant | The conversation, your workspace and role, the candidate or job you have open, and the results of the tools the assistant calls. Tool results can include candidate names and contact details. | Tool results are redacted before the model sees them: candidate names become "Candidate" with a short code, and contact details, links, locations and names in free text are removed. Names you type into the conversation are still sent. |

Anonymization applies to the scoring, matching, note-summary and chat-tool-result
paths above. The chat assistant's conversation itself is not redacted: a name or
contact detail you type is sent as typed. The interview brief is not yet covered.
Treat it as receiving identifying details until this page says otherwise.

What is sent to a provider is limited to the feature you enabled. Candidate
data is personal data, so:

- Choose a provider with a data processing agreement that fits your obligations.
- Tell candidates if AI is part of your review process.
- Review the AI usage log in **Settings → AI → Usage** periodically.
- Keep a documented override path for every material recommendation.

<Info>
  Do not place provider credentials, private notes, or unnecessary candidate
  data into prompts. If you configure a custom system prompt, treat it as
  infrastructure code — review it before enabling.
</Info>

## Turn off AI

Disable individual features in **Settings → AI** without removing the provider.
Remove the API key entirely to disable all AI features and prevent any data
from reaching the provider.

Disabling AI does not affect any other part of Harly. All records, pipelines,
interviews, and offers remain unchanged.
