title: "Email, inbound replies, and mailboxes"
description: "Configure outbound email with Resend or SMTP, set up inbound mailboxes, and route candidate replies back to the application record and shared team inbox."
---

Harly can send candidate email through Resend or SMTP and can route inbound
replies back to the correct application through Resend or Postmark webhooks.

## Outbound email

Open **Settings → Email**, choose a provider, configure the sender identity,
and send a test message to a controlled mailbox before inviting any candidates.

### Resend

1. Create a [Resend](https://resend.com) account and verify your sending domain.
2. Create an API key.
3. Open **Settings → Email → Outbound** and choose **Resend**.
4. Paste the API key and set the sender identity:

   ```text
   Sender name:  Hiring Team
   Sender email: recruiting@example.com
   ```

5. Select **Send test** and confirm delivery.

### SMTP

Open **Settings → Email → Outbound → SMTP** and configure:

```text
Host:     smtp.example.com
Port:     587   (STARTTLS) or 465 (implicit TLS)
Username: recruiting@example.com
Password: <app-password>
From:     recruiting@example.com
```

Use port `465` for implicit TLS or `587` for STARTTLS. Never test with a real
candidate address until the sender domain passes authentication.

## Inbound replies

Inbound replies route candidate responses back to the application thread
automatically. Harly generates a unique `reply+token@domain` address for each
application. Supported providers: **Resend** and **Postmark**.

### Inbound endpoint

The provider webhook must POST to:

```text
https://hiring.example.com/api/webhooks/email/{provider}?ws={workspaceId}
```

Where `{provider}` is `resend` or `postmark`, and `{workspaceId}` is the
workspace ID shown in **Settings → Email → Inbound**.

Harly verifies the provider signature using the webhook secret you configure
in the settings screen.

### Setup steps

<Steps>
  <Step title="Configure the receiving domain">
    In **Settings → Email → Inbound**, enter the receiving hostname — only the
    hostname, not a URL:

    ```text
    replies.example.com
    ```

    Add the provider's MX records for this domain. For Resend inbound, follow
    [Resend's inbound routing guide](https://resend.com/docs). For Postmark,
    create an inbound server and point its MX records at your domain.
  </Step>
  <Step title="Register the webhook endpoint">
    In the provider dashboard, set the inbound webhook destination to:

    ```text
    https://hiring.example.com/api/webhooks/email/resend?ws=<workspace-id>
    ```

    Or for Postmark:

    ```text
    https://hiring.example.com/api/webhooks/email/postmark?ws=<workspace-id>
    ```

    Include the webhook secret shown in Harly's inbound email settings.
  </Step>
  <Step title="Verify">
    Send a message to a test candidate from the Harly inbox. Reply to it from
    an external mailbox. Confirm the reply threads back onto the application
    within one minute.
  </Step>
</Steps>

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| No outbound delivery | Invalid sender domain or credentials | Open **Settings → Email → Delivery log**. Failed rows show the provider's reason in *Last error*; fix the sender, then *Retry* the row |
| Email shows "Queued" for a long time | The worker is not running or the provider is slow | Check the scheduler with the doctor (see [operations](/self-hosting/operations#candidate-email-retries-and-attempts)); queued emails are retried automatically |
| Email shows "Failed" in the Delivery log | Five attempts did not succeed | Fix the cause in *Last error*, then *Retry* it, or *Cancel* it if it is no longer wanted. Cancelled and failed emails are never sent automatically |
| Stage change saved but email warning appeared | The candidate email was not sent right now | The warning says whether a retry is scheduled. If it says it will not be retried, review it in the Delivery log. A warning that says delivery is taking longer than usual means the email is still queued and will finish in the background |
| Email says "Delivery outcome unknown" | The mail server stopped responding after it received the message | Check the sent folder. Harly does not resend it automatically; *Retry* it from the Delivery log only if the recipient did not get it |
| Interview time looks wrong to the candidate | The interview zone was not recorded | Emails show the zone in brackets, for example `(Europe/Madrid)`. Reschedule and cancel emails keep the zone of the original invite. Older queued emails without a zone show `(UTC)` |
| Interview time is rejected: "That time does not exist" | The local time was skipped by a daylight-saving change | Pick a time that exists in the zone. Harly does not move the time silently |
| Reply not threaded | Receiving domain set as URL instead of hostname | Set only `replies.example.com`, not `https://…` |
| Webhook returns 404 | Wrong workspace ID in query param | Copy exact workspace ID from Settings → Email → Inbound |
| Webhook returns 401 | Secret mismatch | Verify the provider has the current secret from Harly settings |
| Duplicate delivery | A crash can happen between the provider accepting an email and Harly recording it | Harly never resends an email the provider accepted. Use the provider message ID (also the `Message-ID` header) to deduplicate at the recipient side if you need a hard guarantee |
