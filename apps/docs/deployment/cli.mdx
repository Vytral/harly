`@harly/cli` is the installer and operator for a self-hosted Harly instance.
Run it with `npx @harly/cli` for the guided menu, or pass a command directly.

```bash
npx @harly/cli [command] [directory] [flags]
```

When no command is given and a terminal is attached, the CLI shows an
interactive menu. In a non-interactive environment it runs `doctor` on any
detected installation, or prints usage.

## Commands

### `harly` (menu)

Guided menu. Detects an existing installation and offers status, update,
backup, restore, or uninstall. Without an installation, offers install or
cloud deploy.

```bash
npx @harly/cli
```

---

### `check`

Verify host requirements without installing. Checks Node.js version, Docker
Engine ≥ 24, Docker Compose ≥ 2.20, and free disk space (≥ 5 GB by default).
Does not check ports or DNS.

```bash
npx @harly/cli check [directory]
```

---

### `init`

Generate a new installation: write `compose.yaml`, `.env` with generated
secrets, `harly.config.json`, a `Caddyfile`, and a `README.md`. Does not pull
images or start services — run `launch` after.

```bash
npx @harly/cli init [directory] [--force] [--dry-run]
```

| Flag | Effect |
| --- | --- |
| `--force` | Overwrite an existing installation in the directory. |
| `--dry-run` | Print what would be written without touching the filesystem. |

**Non-interactive env vars** (skip prompts in CI):

| Variable | Description |
| --- | --- |
| `HARLY_URL` | Public HTTPS origin, e.g. `https://careers.example.com`. |
| `HARLY_PROXY_MODE` | `caddy`, `external`, or `local`. |
| `HARLY_PORT` | App port for `external` and `local` modes (default `3000`). |
| `HARLY_INITIAL_ADMIN_EMAIL` | Email for the first admin account. |
| `HARLY_ORGANIZATION` | Workspace display name. |
| `HARLY_RESOURCE_PROFILE` | `compact`, `standard`, or `performance`. |
| `HARLY_IMAGE_REF` | Override the default image tag. |
| `STORAGE_PROVIDER` | `local` or `s3`. |
| `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_PUBLIC_URL` | S3 credentials when `STORAGE_PROVIDER=s3`. |

---

### `launch`

Pull images and start all services. Run after `init`.

```bash
npx @harly/cli launch [directory] [--yes]
```

`--yes` skips confirmation prompts.

---

### `doctor`

Check service health and public reachability. Use after launch or to diagnose
a running installation.

```bash
npx @harly/cli doctor [directory] [--json] [--fix]
```

| Flag | Effect |
| --- | --- |
| `--json` | Output results as JSON (useful for monitoring scripts). |
| `--fix` | Attempt automatic recovery for common issues. |

---

### `setup-secret`

Print the `HARLY_SETUP_SECRET` from the installation's `.env`. Use this to
complete first-run setup when the setup page asks for it.

```bash
npx @harly/cli setup-secret [directory]
```

---

### `backup`

Write a rollback archive of the database and uploaded files to a `backups/`
folder inside the installation directory. The archive is created with mode
0600.

```bash
npx @harly/cli backup [directory] [--encrypt]
```

`--encrypt` produces an `.age`-encrypted archive. Store the key separately.

---

### `restore`

Restore from a backup archive. Requires `--force` to confirm data replacement.

```bash
npx @harly/cli restore <archive> [directory] --force
```

<Warning>
  Restore replaces the current database and files. Back up the running
  installation first with `harly backup` if you want a rollback point.
</Warning>

---

### `update`

Back up, pull the new image, run migrations, and restart services.

```bash
npx @harly/cli update [directory] [--to version]
```

`--to version` pins the target version, e.g. `--to 1.2.0`, or accepts a full
image reference. Without it, the CLI re-pulls and redeploys the currently
configured image. `--to latest` is rejected — pin a version or use `edge` for
previews.

---

### `uninstall`

Stop and remove Harly. Containers and compose files are removed; data is kept
unless `--remove-data` is passed.

```bash
npx @harly/cli uninstall [directory] [--remove-data]
```

<Warning>
  `--remove-data` permanently deletes the PostgreSQL volume and all uploaded
  files. Back up first.
</Warning>

---

### `deploy`

Generate a cloud-platform config and secrets file. Does not deploy — follow
the printed next steps for each platform.

```bash
npx @harly/cli deploy <railway|fly|digitalocean>
```

| Platform | Output |
| --- | --- |
| `railway` | Prints a Railway setup guide with the image and required env vars. |
| `fly` | Writes `fly.toml` and `.env` (mode 0600). |
| `digitalocean` | Writes `app.yaml` and `.env` (mode 0600). |

See [cloud deployments](/deployment/cloud) for the full per-platform guide.

## Resource profiles

The CLI selects a profile automatically based on free memory, or you can set
`HARLY_RESOURCE_PROFILE` explicitly.

| Profile | App | PostgreSQL | Scheduler | Auto-selected when |
| --- | --- | --- | --- | --- |
| `compact` | 1024 MB | 384 MB | 192 MB | Free RAM after reservations < 1.5 GB |
| `standard` | 1536 MB | 768 MB | 256 MB | Free RAM 1.5–3.5 GB |
| `performance` | 3072 MB | 1536 MB | 512 MB | Free RAM > 3.5 GB |

<Tip>
  Profile selection uses **free** memory, not total RAM. A 4 GB VPS already
  running other services may auto-select `compact`. Override with
  `HARLY_RESOURCE_PROFILE=standard` if you know the headroom is available.
</Tip>

## Proxy modes

Set with `HARLY_PROXY_MODE` or chosen interactively during `init`.

| Mode | When to use |
| --- | --- |
| `caddy` | Harly manages HTTPS via Caddy. Requires ports 80 and 443. |
| `external` | A reverse proxy you control terminates TLS; Harly listens on `HARLY_PORT`. |
| `local` | Development only. HTTP, no TLS, no public domain required. |

See [proxy modes](/self-hosting/proxy-modes) for configuration details.
